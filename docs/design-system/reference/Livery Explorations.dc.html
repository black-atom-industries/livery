4A COLOR MODEL — CHROME IS PAINTED BY THE THEME NO HARDCODED HEX IN COMPONENTS · EVERY LITERAL ON THIS BOARD IS A TOKEN STAND-IN
ThemeProvider injects the selected theme's ui.bg / ui.fg values into the --lvr-* tokens on apply — the whole chrome re-tints with the theme. Dark frames on this board show the chrome as painted by Koyo Yoru; light frames by Spring Day. Components reference tokens only.
TOKEN MAP · MOCK HEX → TOKEN → THEME SOURCE
page background--lvr-color-bg-defaultui.bg.default
primary text--lvr-color-fg-defaultui.fg.default
raised bars, panels--lvr-color-bg-subtleui.bg.panel
secondary text--lvr-color-fg-subtleui.fg.subtle
selected row--lvr-color-bg-accentui.bg.active
labels, hints--lvr-color-fg-hintui.fg.hint
primary button, active chip--lvr-color-bg-contrastui.bg.contrast
disabled, dimmed--lvr-color-fg-disabledui.fg.disabled
synced, ok pips, focus--lvr-color-fg-positiveui.fg.positive
warn pips, attention--lvr-color-fg-warnui.fg.warn
error pips, faults--lvr-color-fg-negativeui.fg.negative
info--lvr-color-fg-infoui.fg.info
DERIVED TOKENS · NOT IN theme.ui — DERIVE IN CSS, DO NOT HARDCODE
borders, rules--lvr-color-border-default: color-mix(in oklch, var(--lvr-color-fg-default) 18%, transparent)
soft rules, dividers--lvr-color-border-subtle: color-mix(in oklch, var(--lvr-color-fg-default) 10%, transparent)
recessed: inputs, code, prompt--lvr-color-bg-recessed: oklch(from var(--lvr-color-bg-default) calc(l - 0.035) c h) /* +0.035 in light via light-dark() */
Swatches, accent bands and the code preview are the exception: they render the theme's raw palette values directly (primaries, ANSI, accents) — that data is display content, not chrome.
